# Study Note

把用户刚学到的内容整理成简洁、可独立回看的 Markdown 笔记。

## 工作流

1. 读取 `PROGRESS.md` 的“当前位置”，确定当前周次。
2. 确定主题：
   - 用户给出主题或范围时，以用户要求为准。
   - 用户未给出主题时，从本次对话中选取最近学到或踩坑的一个具体知识点。
   - 无法可靠判断时，简短询问用户想记录哪个点，不要擅自扩大范围。
3. 检查 `notes/` 中已有文件，遵循命名和追加规则：
   - 使用 `notes/第X周-主题.md`，主题采用简短关键词。
   - 同一主题文件已存在时追加新记录，保留旧内容；不存在时新建并写一级标题。
4. 只记录用户已经实际学习、操作或验证过的内容，不把尚未学习的后续步骤写成“已经掌握”。
5. 使用当前日期记录时间；除非用户明确要求，不修改 `PROGRESS.md`。
6. 写入后检查 Markdown、命令和文件差异，确认未覆盖旧笔记。
7. 告知用户文件路径，以及本次是新建还是追加；提醒笔记可作为 `/study-review` 的复盘证据。

## 单条笔记结构

保持简洁，并按内容删掉不适用的小节：

```markdown
### 🗒️ 知识点或踩坑名称（记录时间：YYYY-MM-DD）

- **是什么**：用直接、准确的话说明；只有抽象难懂时才补简短类比。
- **踩了什么坑 / 卡在哪**：仅在确实发生过时填写。
- **怎么解决的 / 正确做法**：写清判断依据和操作顺序。
- **关键代码或命令**：有必要时使用带语言标识的代码块。
- **一句话记住它**：给出便于以后回忆的结论。
```

如果用户要求整理一组紧密相关的操作，可以在同一个主题文件中写多条上述记录；不要为了凑结构重复内容。

## 内容标准

- 面向隔一个月后回看的用户，补足必要上下文，但不要写成长篇教程。
- 保留真实错误、错误原因、正确写法和如何识别错误信息。
- 命令必须可复制，区分终端命令、SQL、Java 和配置文件内容。
- 避免对每个简单概念都做前端类比；直接解释能讲清时就直接解释。
- 不记录敏感信息。示例中的密码、令牌和生产地址使用占位符。
- 不声称用户已经掌握未经自检或验证的内容。
